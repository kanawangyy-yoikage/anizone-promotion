🚨 Masalah: Firebase Security Rules terlalu ketat
Test update atau delete gagal dengan error PERMISSION_DENIED.
Ini bukan bug di kode JS — ini Rules Firestore yang belum mengizinkan operasi tersebut.

👉 Klik tab "Fix Rules" untuk lihat rules yang perlu dipasang.
✅ Semua permission OK
Firebase mengizinkan semua operasi. Jika like/edit masih tidak bisa, kemungkinan ada bug lain di kode — cek tab Manual Test untuk debug lebih lanjut.
Cara Fix di Firebase Console
1. Buka console.firebase.google.com
2. Pilih project: promo-anizone
3. Sidebar kiri → Firestore Database
4. Tab Rules di bagian atas
5. Hapus semua teks yang ada
6. Copy-paste rules di bawah ini
7. Klik tombol Publish
FIRESTORE SECURITY RULES
rules_version = '2'; // AniZone 2026 — Security Rules service cloud.firestore { match /databases/{database}/documents { // ── Komentar ────────────────────────── match /comments/{commentId} { // Siapa saja bisa baca komentar allow read: if true; // Buat komentar baru: validasi panjang allow create: if request.resource.data.text.size() <= 500 && request.resource.data.username.size() >= 3 && request.resource.data.username.size() <= 30; // Update: izinkan edit teks DAN update likes allow update: if true; // Delete: izinkan (user hanya bisa hapus komentarnya sendiri // — validasi di sisi klien sudah cukup untuk use-case ini) allow delete: if true; } // ── Profil User ──────────────────────── match /users/{userId} { allow read: if true; allow write: if true; } } }
⚠️ Catatan keamanan: Rules ini mengizinkan semua update/delete tanpa autentikasi, cocok untuk project edukasi/portofolio. Untuk production serius, tambahkan Firebase Auth.
